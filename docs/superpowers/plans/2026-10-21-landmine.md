# landmine: implementation plan

**Spec:** `docs/superpowers/specs/2026-10-21-landmine-design.md`

**Execution:** inline, by the session that wrote the spec. The owner pre-approved the
method (DECISIONS D-19).

## The gate for every milestone

```
npm run typecheck && npm run lint && npm test
```

All three must pass before committing. Commits use the style
`feat(scope): …`, `test: …`, `docs: …`, with the Co-Authored-By trailer. After each
commit, `docs/PROGRESS.md` is updated.

## Conventions

- **TypeScript.**
  - Strict mode, with `noUncheckedIndexedAccess`.
  - ESM only: `"type": "module"`, NodeNext resolution, and `.js` suffixes on
    relative imports.
- **Dependency injection.**
  - Every network caller takes a `Http` object, `{ fetch: typeof fetch }`.
  - Every filesystem reader takes paths, never relying on implicit cwd.
  - Time comes from an injectable `now()`.
- **Offline tests.**
  - `test/setup.ts` replaces `globalThis.fetch` with a function that throws.
  - Fixtures live in `test/fixtures/`.
- **Pure analysis.** Files under `analyze/`, `source/` and `match.ts` contain pure
  functions with no I/O.

## M1: Lockfiles → direct dependencies

- `src/lockfiles/npm.ts`: package-lock v1/v2/v3 and shrinkwrap
- `src/lockfiles/pnpm.ts`: 5.4/6/9, multi-document, peer suffix, aliases
- `src/lockfiles/yarn.ts`: v1 custom parser and berry via js-yaml, joined with
  package.json
- `src/lockfiles/bun.ts`: JSONC via a small trailing-comma-tolerant parser built on

  function in `src/util/jsonc.ts`.
- `src/lockfiles/python.ts`:
  - requirements, including `-r` recursion and the pin rules

- `src/lockfiles/index.ts`:
  - `findProjectRoot(start)`
  - `readDependencies(root, {prod})`, which picks lockfiles by priority, merges
    ecosystems, and dedupes by (ecosystem, name)
  - returns `{ deps, lockfiles, skipped }`

**Fixtures:** copy the real lockfiles generated during research from
`/tmp/lmresearch-a1/*` into `test/fixtures/lockfiles/<case>/`:
- npm: npmv1, npmv2, npmproj (v3, workspaces, aliases, git), npmfile

**Tests** (one file per format):
- the exact expected direct-dependency list
- dev flags
- alias resolves to the real name
- link, workspace and git entries are skipped
- requirements edge cases: extras with commas, markers, hashes, continuations, `-r`,
  and unpinned lines skipped

## M2: Source analysis

**Files:**
- `src/source/lex.ts`:
  - `blank(text, lang)` returns text of equal length, with comments replaced by
    spaces and string contents by spaces. Quotes and newlines stay.
  - `strings(text, lang)` returns `[{start, end, value}]`.
- `src/source/specifier.ts`: `packageFromSpecifier(spec)`, with a builtin list from
  `node:module` `builtinModules`.
- `src/source/jsImports.ts`: `jsBindings(text) → Binding[]`.
- `src/source/pyImports.ts`: `pyBindings(text) → Binding[]`, where the package is
  the top-level module name.
- `src/source/aliases.ts`: one-level derived aliases.
- `src/source/touches.ts`:
  - `touches({fileText, changedText, lang, resolvePackage}) → Map<pkg, Set<symbol>>`
  - walks chains and JSX tags
- `src/source/lang.ts`: extension → `'js' | 'py' | null`.

**Tests:**
- table-driven bindings for every import form in spec §7, including type-only
  skipping and broken mid-edit files where the error comes before the imports
- chain walking: `z.string().email()`, `db.$client.end()`,
  `requests.Session().mount`, optional chaining, generics, and the 6-segment cap
- Python parenthesized and multi-line imports, `as` aliases, relative imports
  skipped
- comments and strings do not create bindings

**Commit:** `feat(source): tolerant import and symbol-usage analysis for JS/TS and Python`

## M3: HTTP, GitHub client, registries

**Files:**
- `src/http.ts`:
  - `Http` type
  - `createRecordingHttp(dir)` and `createReplayHttp(dir)`, keyed by
    `sha1(method + url + body)`
- `src/github/token.ts`: env first, then `gh auth token` via `execFile` with a 3 s
  timeout.
- `src/github/client.ts`:
  - `graphql(query, vars)` and `rest(path)`
  - headers: User-Agent, `X-GitHub-Api-Version: 2026-03-10`, Accept
  - 403/429 backoff per spec §5
  - concurrency limiter (2)
- `src/registry/repoUrl.ts`: `parseGitHubRepo(any) → {owner, repo} | null`, covering
  every shape in RESEARCH §3.
- `src/registry/npm.ts` and `src/registry/pypi.ts`:
  `resolveRepo(dep, http) → RepoResolution`, including PEP 753 labels and the
  sponsors trap.
- `src/github/repos.ts`: `canonicalRepo(owner/repo)` returns `full_name`,
  `archived` and `has_issues`.
- `src/github/issues.ts`: `searchVersionIssues(repo, version, max)` (GraphQL, 25 per
  page) returns `RawIssue[]` plus `searchHits`.

**Fixtures:** `scripts/record-fixtures.ts` records:
- npm metadata for zod, @tanstack/react-query, next, drizzle-orm
- PyPI metadata for requests, pydantic, fastapi, beautifulsoup4
- repos for fastapi/fastapi (rename) and drizzle-team/drizzle-orm
- one GraphQL search for drizzle-orm 0.36.0

**Tests:**
- `parseGitHubRepo` table
- npm and PyPI resolution against replayed fixtures
- client backoff and retry using a fake `Http` that answers 403 with `retry-after`,
  with a fake sleep
- GraphQL pagination stops at max
- replay `Http` throws on unknown requests

**Commit:** `feat(github): GitHub, npm and PyPI clients with recorded-fixture tests`

## M8: Real end to end, plus accuracy

1. **Build the demo.** `examples/demo/` gets a `package.json` plus a real
   `package-lock.json` (`npm install --package-lock-only`), pinned to versions found
   in the probe to have open bugs. Add small source files that use the affected
   symbols, and a Python part with `requirements.txt`.
2. **Run the CLI for real.** `node dist/cli.js scan` (live network), then `check`,
   then `install`. Save outputs to `docs/e2e/`.
3. **Run a live Claude Code session.** `claude -p` in the demo, with the hook
   installed in the demo's `.claude/settings.json`, prompting an edit that uses a
   landmined symbol. Capture the transcript and the hook payload (debug log) to
   `docs/e2e/claude-session.md`. Replace the hand-built Claude payload fixture with
   the captured one.
4. **Try Codex.** If `codex exec` can run non-interactively with
   `--dangerously-bypass-hook-trust` in the demo, record it. Otherwise record why
   not.
5. **Measure accuracy.** `scripts/accuracy-sample.ts` takes a seeded random sample
   from real scans of the demo plus two other real projects. Hand-label it into
   `docs/ACCURACY.md`. Tune thresholds only on a separate tuning sample, and report
   the held-out numbers.

**Commit:** `test(e2e): real scan, live Claude Code session, accuracy sample`
