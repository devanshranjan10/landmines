# landmine v0.2: implementation plan

Spec: `docs/superpowers/specs/2026-10-21-landmine-v0.2-design.md`.

The gate is the same as v0.1. Every milestone ends with these, then a commit:
- `npm run typecheck`
- `npm run lint`
- `npm test` (offline)
- `npm run build`

PROGRESS.md is updated at each commit.

## M11: Bench tasks and validator
- `bench/tasks/<slug>/`:
  - `task.json` (issue, package@version, ecosystem, tier, entry file, test command)
  - `TASK.md`
  - seed source
  - `hidden/` test
  - `reference/naive.*` and `reference/fixed.*`
- `bench/env/`: a shared npm install per task, and one uv venv (Python 3.12) with every
  pinned Python package.
- `scripts/bench/validate.ts`: for each task, copy to temp, apply naive, then run
  hidden (must fail). Apply fixed, then run hidden (must pass). Writes
  `bench/validation.json`.
- `bench/split.json`: a seeded dev/test split, frozen and committed before any tuning.
- Verify: validate passes for every kept task. Dropped tasks are listed with a reason.

## M12: Trap runner and pilot (`none` arm, dev split)
- `scripts/bench/run.ts --arm <a> --split dev|test --agent claude --seeds n`:
  1. Materialise the task in a temp dir.
  2. Prepare the arm: index, hook settings, rules section, MCP.
  3. Run the agent headless.
  4. Copy out the final source.
  5. Run hidden tests.
  6. Write `bench/results/<run>.json`: pass, fired, cited, turns, cost, time.
- Pilot: `none` on dev with 1 seed. This gives per-run cost and whether traps trap.
- Verify: the result JSONs exist and the costs are summed.

## M13: `landmine rules` and `check --staged`
- `src/rules.ts`: renders the known-issues section from the index (armed landmines
  ranked, capped), with marker comments so it can be rewritten idempotently in any
  markdown file.
- CLI: `landmine rules [--write <file>] [--max n]`, and `landmine check --staged`.
- Tests: rendering, idempotent rewrite, marker preservation, staged diff parsing
  (fixture git repo).

## M14: Harness adapters
Driven by the synthesis.
- New payload shapes go in `src/hook/payload.ts`, respond formats in `respond.ts`, and
  install targets in `install.ts`.
- The OpenCode/Kilo plugin template.
- One recorded-payload test per harness, taken from source or docs.
- A live run where the CLI is logged in: opencode and cline are installed.

## M15: Trigger cards
- `src/llm/` holds the providers (anthropic, openai, claude-cli, codex-cli) with an
  injected transport, so tests replay recorded responses.
- `src/cards.ts`:
  - the prompt (versioned)
  - parse and validate
  - self-validation against the issue's repro fence
  - the cache
- `match.ts` matches cards by the spec §5.2 rules.
- The `scan --cards` and `cards` commands.
- Index track: compare cards against the 40 human labels.

## M16: Full bench
- Run arms `none`, `rules`, `hook`, `hook+cards` on the test split, with the seeds the
  pilot allows.
- Run the false-interrupt track for all configurations.
- Write `docs/BENCHMARK.md`, the README headline, ACCURACY updates and the PROGRESS
  morning summary.
