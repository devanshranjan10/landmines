# landmine v0.2: benchmark, trigger cards, every harness

Date: 2026-10-21. Status: self-approved under the owner's standing pre-approval
(D-32). Research is in `docs/RESEARCH.md` §8–§10, which summarises three reports:
- the eval and benchmark survey
- the trap-task spike
- the harness hook survey

## 1. Understanding

**What the owner asked for.**
> Now run the evals and benchmarks and achieve SOTA in this and make it such that it
> works with any harness and hooks and stuff like CC, codex, opencode, antigravity,
> kilo code, cline, freebuff and any other coding agent … make it SOTA and the best tool.

**What "SOTA" can honestly mean.** No public benchmark measures this task: downstream
code plus a lockfile → the open upstream bug this edit is about to hit → interrupt
the agent. GitChameleon, VersiCode and CodeUpdateArena measure version API drift.
SWE-bench/LocBench measure localisation inside one repo. Claiming SOTA on any of
them would be a category error.

The only defensible form is to build the benchmark, freeze it, run named baselines on
it, and report which arm wins with confidence intervals. That is how GitChameleon and
ImpossibleBench established their own leaderboards. "SOTA" in every user-facing doc
therefore means: **best measured arm on landmine-bench v0 against the named
baselines**, never a broader claim.

**Constraints carried over.** No publishing, no remotes, no posting. Every README
claim must have been run. Small milestones, each gated by typecheck, lint, tests and
a commit. Offline tests. Budget for live agent and LLM calls: about $100 (owner's
answer to the process question, 2026-10-21).

## 2. What v0.1 measured, and what it implies

- Symbol-only matching was about 90% noise on real code.
- Corroboration made the hook precise but rare: 1 block in 60 held-out files.
- Index precision: about 82% version-correct and 45% top-symbol-correct.
- Recall was never measured.
- The trap spike showed what the heuristics miss. Of 35 reproducible open bugs, 7 have
  **no armed symbol at all**, for example dayjs#2901 `dayjs('600','Hmm')` and
  numpy#27674 `np.ptp(masked)`. Several others are armed only on prose words
  (`option.The`, `failure`).

The heuristic symbol extractor cannot see the bug's *trigger*: the API plus the
argument, option or data shape that makes it fire. That is the precision and recall
lever.

## 3. Approaches considered

| Approach | Verdict |
|---|---|
| A. Tune heuristics further on the trap set | Rejected. Overfits 35 tasks and cannot learn triggers like "format string `Hmm`". |
| B. LLM judge in the hook, every edit | Rejected as the default. It adds 3–7 s and a network call to every matching edit, needs a key, and is non-deterministic. |
| **C. Trigger cards at scan time (chosen)** | An LLM reads each issue once and writes a structured card: the bug's API, the trigger tokens that must also be present, a one-line condition, and the workaround quote. The hook stays offline, deterministic and fast. It is the QLCoder pattern: synthesise the rule offline, check it cheaply online. |
| D. Static context file only | Kept as a product feature and as a baseline arm. Vercel's evals found a passive AGENTS.md index beat on-demand skills, so it is the most dangerous competitor and must be measured, not assumed away. |

Cards are opt-in: they need an LLM provider. Without one, v0.1 behaviour is unchanged.

## 4. landmine-bench v0

All of it lives in `bench/`. The npm tarball does not ship it.

### 4.1 Trap track (end-to-end, live agents)

- **Tasks.** One task per solid trap from the spike, 35 in all. Each task has:
  - a pinned project (lockfile, plus `node_modules` or a uv venv at the exact version);
  - `TASK.md`, the prompt given to the agent. It reads like a normal ticket and never
    mentions the bug.
  - seed source, where the agent is expected to edit;
  - `hidden/` tests the agent never sees, validated fail→pass: the naive solution fails
    and the workaround passes.
- **Validation is executable.** Every task ships `reference/naive.*` and
  `reference/fixed.*`. `bench validate` asserts naive fails and fixed passes. Tasks
  failing that are dropped and reported.
- **Split.** A seeded shuffle, frozen in `bench/split.json` *before* any card or prompt
  tuning: about ⅓ dev, ⅔ test. Tuning may only look at dev results. Test numbers are
  reported once per configuration and never iterated on.
- **Arms.**
  1. `none`: the agent alone.
  2. `rules`: the static known-issues section `landmine rules` writes into
     AGENTS.md/CLAUDE.md for the project's index.
  3. `hook`: the v0.1 default hook (heuristic, block only when corroborated).
  4. `hook+cards`: the v0.2 hook with trigger cards.
  5. Optional `mcp`: the landmine MCP server only (pull), if budget remains.
- **Agent.** Claude Code headless (`claude -p`), with a fixed model, a fixed turn cap
  and no other MCP servers or settings (`--setting-sources` limited to the project).
  Codex is a second agent if the pilot shows budget for it.
- **Metrics per run.**
  - hidden-test pass (the headline: "avoided the bug");
  - whether the agent's final code calls the buggy API in the triggering way (static
    check per task);
  - whether landmine fired and cited the issue;
  - turns, cost and wall time.
- **Statistics.** Pass rate per arm with Wilson 95% CIs. Paired comparison against
  `none` with an exact McNemar test (same tasks, same seed index). Seeds per
  (task, arm) depend on the pilot cost.

### 4.2 False-interrupt track (offline, deterministic)

Run the hook in every configuration over the held-out real-code set C3 (60 files from
60 repos, already labelled) and over each trap task's *workaround* solution. Metric:
blocks per file, and the share that are relevant. A tool that fires on the workaround
is nagging the user who already avoided the bug.

### 4.3 Index track (offline)

Re-label nothing new. Compare heuristic symbols with card APIs on the existing
hand-labelled 40-issue sample (`eval/labels`). Measure:
- top API correct;
- non-bug detection;
- workaround genuine.

The LLM card is scored against the human labels. Agreement is reported as Cohen's κ.

### 4.4 What gets published in the repo

`docs/BENCHMARK.md` holds:
- the protocol;
- the frozen split;
- per-arm tables with CIs;
- every run's JSON in `bench/results/`;
- the costs;
- the things that went wrong.

The README headline is the test-split table, whatever it says.

## 5. Trigger cards

### 5.1 Data model (index schema 2, backwards compatible)

```ts
interface TriggerCard {
  isBug: boolean;                  // false → never arms
  affectsPinned: 'yes' | 'likely' | 'no' | 'unknown';
  apis: string[];                  // e.g. ["dayjs", "Duration.add", "add"]: what the edit must touch
  requires: string[][];            // AND of OR-groups of tokens the file must contain, e.g. [["duration"], ["weeks"]]
  condition: string;               // one line: "dayjs().add(dayjs.duration({ weeks })) ignores weeks"
  workaround?: string;             // short, verbatim-or-paraphrased fix, attributed to a comment URL
  workaroundUrl?: string;
  confidence: number;              // 0..1, the model's own
  model: string; provider: string; promptVersion: number;
}
```

`Landmine.card?: TriggerCard`. Schema stays `1`. The field is optional, so v0.1
readers ignore it.

### 5.2 Matching with a card

A landmine **with** a card fires (block) when all of these hold:
1. The edit touches one of `card.apis`. The match uses the same touch extraction, and
   names are compared on the last segment as well as fully qualified.
2. Every group in `card.requires` has at least one token present in the *edited file*,
   as an identifier, string literal content or option key.
3. `card.isBug && card.affectsPinned !== 'no'`.

A landmine **without** a card keeps v0.1 behaviour. The card replaces heuristic
corroboration for that issue: a card is the evidence.

### 5.3 Self-validation (drop bad cards)

Reject a card, falling back to the heuristics, when:
- an API is not an identifier-like string;
- `requires` is empty while `apis` holds only a generic entry point (`DataFrame`,
  `dayjs`, `np`);
- the issue's own repro code fence does not match the card under §5.2 rules. This only
  applies when the issue has a code fence in a language landmine parses.

### 5.4 Providers (`src/llm/`)

| Provider | How | Notes |
|---|---|---|
| `anthropic` | HTTPS `POST /v1/messages`, `ANTHROPIC_API_KEY` | default model `claude-haiku-5-5` |
| `openai` | OpenAI-compatible `/chat/completions`, `OPENAI_API_KEY`, `OPENAI_BASE_URL` | covers OpenAI, OpenRouter, Ollama, LM Studio, vLLM |
| `claude-cli` | `claude -p --output-format json --tools "" --system-prompt … --setting-sources "" --strict-mcp-config --no-session-persistence` | uses an existing Claude Code login; measured ~$0.003 and 3–5 s a call |
| `codex-cli` | `codex exec --json` read-only | uses an existing Codex login |

- Tests use recorded responses only.
- Cards are cached in `.landmine/cache/cards/<hash>.json`. The key is
  (issue updatedAt, prompt version, model), so re-scans cost nothing.
- Third-party issue text is wrapped and labelled as untrusted in the prompt.
- The card's strings are length-capped and pass through the existing message
  sanitiser before reaching an agent.

CLI: `landmine scan --cards <provider> [--model m] [--max-cards N]` and
`landmine cards <provider>` to enrich an existing index.

## 6. Every harness

The harness survey (RESEARCH §10) sorts agents into four groups:

1. **Shell hook, payload shape already supported**: install target only.
2. **Shell hook, new payload shape**: a new adapter in `src/hook/payload.ts` plus a
   respond format.
3. **JS/TS plugin systems** (OpenCode, Kilo, and anything else built on OpenCode):
   `landmine install --harness opencode` writes a small plugin. It runs
   `landmine hook --harness opencode` on `tool.execute.before` and throws with the
   message once.
4. **No pre-edit hook**: MCP config plus the rules section. Where a post-edit
   diagnostics channel exists, it is documented.

The concrete per-agent table and field mappings come from the synthesis and are
recorded in RESEARCH §10 and the README "Harnesses" table. Each row is labelled
**live-verified**, **payload-replayed** or **built from docs**.

Universal fallbacks that work with any agent:
- `landmine rules [--write AGENTS.md|CLAUDE.md|GEMINI.md|…]` writes a short,
  marker-delimited "Known open bugs in your pinned dependencies" section. It lists
  armed issues with their trigger and workaround, capped at N entries ranked by
  confidence.
- `landmine mcp` (exists).
- `landmine check --staged` for a git pre-commit hook. It exits non-zero on a
  corroborated or card hit.

## 7. Out of scope for v0.2

- Hook-time LLM judging.
- Version-range recall (issues naming a nearby version). Research found it is likely
  the largest recall gap. It is recorded as the top "next" item and not attempted
  here, because measuring it needs the time-travel recall set.
- A live run in every harness. Live runs happen where a CLI is installed and logged
  in. The rest is replayed from documented or source-derived payloads, and labelled
  as such.

## 8. Risks

- **Agents may avoid the traps without help.** Strong agents test their code, so
  `none` may score high. Then the result is reported as it is, along with
  turns and cost saved.
- **Cards could overfit the dev split.** The prompt is written once from the spike's
  dev tasks. Test results are reported once.
- **Budget.** Pilot first. Pick seeds from measured per-run cost.
- **Contamination.** Models may know old issues (all 2024–2025). Reported as a
  limitation. `none` is the control for it.
