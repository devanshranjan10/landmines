## Morning summary (2026-10-21)

### What works (each item verified by running it)

- **Scan on real projects.**
  - `examples/demo` (7 deps): 71 open issues filed against its exact versions, 53 tied
    to symbols, 26 with a workaround. 13 s, live.
  - Two held-out projects with 31 and 44 popular packages scanned live in 50–60 s
    each.
- **Lockfiles.** npm v1–3, pnpm 5.4/6/9 (including multi-document files), yarn
  classic and berry, bun.lock, uv.lock, poetry.lock, Pipfile.lock, pinned
  requirements. Tested on lockfiles generated by the real tools or taken from public
  repos.
- **The hook, live in Claude Code 2.1.304, run three times; the last run used the
  final build.**
  - The agent's own first edit, `db.$client.end()` on drizzle-orm 0.36.0, was denied
    once, citing drizzle-orm#3402 with the quoted workaround.
  - The agent changed approach, using an owned `pg.Pool`, and told the user why.
  - The retry went through.
- **The hook, live in Codex CLI 0.159.0.** Same result with `apply_patch`, on an earlier
  build. The captured payloads replay against the final code in the tests. Also
  verified: without hook trust, Codex does not run the hook.
- **MCP server, live in Claude Code.** It called `landmine_search` and found
  pydantic#10544 for the pinned 2.9.2. The `.mcp.json` from `install --mcp` connects.
- **The rest of the CLI.**
  - `install`/`uninstall` merge idempotently and keep foreign hooks.
  - `check`, `list` and `--exit-code` work.
  - Hook latency is 0.09 s.
  - `npx --package=./landmines-0.1.0.tgz landmines …` works from an empty directory.

### What doesn't, or isn't proven (read `docs/ACCURACY.md`)

- **The interruption is rare, and not yet proven useful on random code.** On a
  held-out set of 60 real files from 60 repos, the default hook would block 1 file,
  and that block was a near miss. The only clearly relevant block we have is the
  drizzle#3402 demo, where `db.$client.end()` was the agent's own unprompted choice.
- **Symbol-only matching is mostly noise.** About 90% of matches did not apply to the
  code: 25 of 28 on C1, and 25 of 27 heads-ups on C3. Usually that was the right API
  without the bug's triggering condition. So weaker matches are now **off by default**
  (D-29), and blocking needs corroboration (D-27).
- **Index precision on held-out samples (n=40, one labeller, me):**
  - version correct: 78% before fixes and 82.5% after the first round. 6 of the
    remaining misses were PyTorch nightlies, fixed afterwards.
  - top symbol is the bug's API: about 45%, plus about 10% partly. Most misses are
    inert names that never fire.
  - workaround genuine: 4 of 9.
- **Recall is not measured.** Only issues that name the exact version string are found,
  and GitHub search itself is unstable from run to run.
- **Cursor and Gemini CLI were not run live.** Cursor wasn't logged in and Gemini isn't
  installed. Both adapters are built from their docs (and the cursor-agent binary).
- **Codex was not re-run live after the final rule changes.** It is covered by replaying
  its real payloads.
- **The npx install path writes a hook command that needs a published package.** It is
  `npx -y landmines@0.1.0 hook`. Until the package is published, install from the
  built checkout.

### Needs your decision

1. **Direction, given the accuracy results.** Three honest options:
   - (a) Ship as is with the honest numbers: rare, explained interruptions, plus the
     `scan` headline report and MCP lookups.
   - (b) Add an opt-in LLM relevance check: does this code meet the bug's condition?
     That is the biggest precision lever; it was deferred in D-05 for cost and
     determinism.
   - (c) Reposition around `scan` (the "N open bugs in your exact versions"
     screenshot) and the MCP lookup, rather than the interrupt.
2. **Publish?** `landmines` was free on npm on 2026-10-21; `landmine` is squatted. The
   bins are `landmine` and `landmines`. Nothing was published or pushed (hard rule).
3. **Repo contents before going public.** Before any repo goes public, review:
   - `docs/e2e/*.jsonl`: my local agent transcripts, with tool inventories and home
     paths redacted
   - `eval/` and `test/fixtures/http/`: public GitHub issue text
4. **The heads-up default** (off) and the block-once-per-session policy.
5. **License.** MIT is assumed.
6. **Positioning.** The original pitch said "GitHub MCP covers vulnerabilities only".
   That is false, and the README uses corrected wording (D-06).
