How it works

Lockfile in. Known bugs out. Before the edit.

01 · scan

Find the issues for your exact versions

Lockfile → exact versions → open GitHub issues that name them. Every hit is checked for the version, tied to code symbols, and given the most useful workaround from its thread. Optional: cards has a model read each issue once and write down what triggers it.

npm · pnpm · yarn · bun · uv · poetry · pip
02 · tell the agent first

A short known-bugs list where it reads

A marker-delimited section in AGENTS.md / CLAUDE.md, ranked by the APIs your code actually uses, with the condition and workaround for each. Issue text is framed as untrusted.

measured: 86% → 99%
03 · backstop

Hook, MCP server and pre-commit

A pre-edit hook that pauses a matching edit once, an MCP server for "is this error a known bug?", and check --staged for CI. All offline after the scan.

The fine print

What the numbers do and don't say.

Our benchmark

No public benchmark measures this, so the numbers come from landmine-bench, which we built. Frozen splits, confirmation runs written down before they ran, and every run published. Method and caveats.

Selection

Every trap is a bug landmine had already indexed. The benchmark measures whether landmine helps once a bug is in its index, not how many bugs it finds. Only open issues that name your exact version are found.

Prompt wording

With fully specified prompts the agent already avoids most traps (19/21 unaided against 21/21 with landmine). The gap shows up when the request reads like a real one.

The hook alone

The pre-edit hook didn't measurably beat no help. Telling the agent up front did, which is why the command above writes the rules section first.
