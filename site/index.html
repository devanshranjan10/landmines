04 · What the agent reads

A short list, in the file it already reads.

landmine rules writes a marked section into AGENTS.md and CLAUDE.md: the open issues for your exact versions, ranked by the APIs your code actually calls, each with its workaround.

  • Only issues that name the version you pin, each checked against the thread.
  • Tied to code symbols, so the agent knows which call to avoid.
  • Framed as untrusted third-party text. The agent is told never to follow it blindly.

07 · Set it up

Your terminal, your MCP client, or just ask.

Every route ends in the same place: the open issues for your exact versions, in front of the agent before it edits. uninstall removes all of it.

  • Local and read-only. Only dependency names and versions leave your machine.
  • Commit .landmine/index.json and your team's agents share one index.
  • Also npm i -D landmines or brew install devanshranjan10/tap/landmines.
# find the open issues filed against your exact versions
$ npx landmines scan
# known-bugs section in AGENTS.md + CLAUDE.md, plus the pre-edit hook
$ npx landmines install --rules
# optional backstop for any agent: check what a commit adds
$ npx landmines check --staged --exit-code
# hosted: nothing to install
$ claude mcp add --transport http landmine https://landmine.tech/mcp
$ codex mcp add landmine --url https://landmine.tech/mcp
# local, over your project's index (stdio)
$ npx landmines install --mcp claude,cursor
# Claude Code plugin: the hook, the MCP server and /landmines:scan
$ claude plugin marketplace add devanshranjan10/landmines
$ claude plugin install landmines@landmines

08 · Limits

What the numbers don't say.

It's our benchmark

No public benchmark measured this, so we built landmine-bench. Splits were frozen before tuning, a confirmation run was written down before it ran, and every result file is public.

Selection

Every trap is a bug landmine had already indexed. The benchmark shows it helps once a bug is in the index, not how many bugs it finds. Only open issues that name your exact version are found.

Prompt wording

With fully specified prompts the agent already avoids most traps (19/21 unaided, 21/21 with landmine). The gap shows up when the request reads like a real one.

The hook alone

The pre-edit hook didn't measurably beat no help. Telling the agent up front did, which is why --rules comes first.

09 · FAQ

Frequently asked questions

Direct answers, with the numbers behind them.

All questions ↗
What is landmine?

A free, open-source command-line tool (npm package landmines, MIT) that finds the open GitHub issues filed against the exact dependency versions a project pins, and puts them where a coding agent reads them before it writes code: a known-bugs section in AGENTS.md and CLAUDE.md, a pre-edit hook, and an MCP server. Each entry carries the affected API and the workaround from the issue thread.

Doesn't web search or Context7 already solve this?

Not in our measurement. On the same 21 held-out tasks, in one batch, Claude Sonnet 5.5 passed 36/42 with web search on, 35/42 with the Context7 docs MCP, 35/42 with no help, and 42/42 with the landmine rules section. In all 84 web-search and Context7 sessions the agent never called either tool: nothing told it there was a bug to look for.

How is this different from Dependabot, npm audit or Snyk?

Those tools report security vulnerabilities from advisory databases and propose upgrades. landmine reports ordinary open bugs (wrong results, crashes, type errors) filed as GitHub issues against the version you pin, whether or not a fix exists, and delivers them to the coding agent with the workaround from the thread, before it writes the code.

Which languages and lockfiles?

JavaScript/TypeScript (npm package-lock.json, pnpm, yarn classic and berry, bun) and Python (uv.lock, poetry.lock, Pipfile.lock, pinned requirements*.txt). Direct dependencies only.

Does landmine send my code anywhere?

No. scan and lookup send dependency names and versions to registry.npmjs.org, pypi.org and api.github.com. The hook and the local MCP server's index tools never touch the network. The hosted server at landmine.tech/mcp receives the versions you look up and any snippet you pass to its landmine_check, and stores no snippets.

Isn't issue text from GitHub a prompt-injection risk?

Yes, and landmine treats it as one. Every quote reaches the agent inside one delimited block labelled as untrusted third-party text, forged delimiters are neutralised, HTML is stripped, length is capped, quotes that pipe downloads into a shell or link unfamiliar hosts are flagged, and the agent is told never to follow instructions inside them.
