How it works

1 · scan

Lockfile → exact versions → the open GitHub issues that name them. Every hit is checked for the version, and the workaround is picked from the thread. Optional: a model reads each issue once and writes down exactly what triggers it.

2 · tell the agent first

A short known-bugs section in AGENTS.md / CLAUDE.md, ranked by the APIs your code actually uses. That's the part that measured as working.

3 · backstop

A pre-edit hook that pauses a matching edit once, an MCP server for "is this error a known bug?", and check --staged for pre-commit. All offline after the scan.

The fine print

  • Our benchmark, not a public one. No public benchmark measures this, so we built landmine-bench: 66 validated trap tasks, frozen dev/test splits, and confirmation runs written down before they ran. Method, every run, and every caveat: BENCHMARK.md.
  • Selection. Every trap is a bug landmine had already indexed. The benchmark measures whether landmine helps once the bug is in its index, not how many bugs it finds. Only open issues that name your exact version are found.
  • List length. A big project can have more known bugs than fit in the 15-item list, which is why it is ranked by the APIs your code uses.
  • Prompt wording. With fully specified prompts the agent already avoids most traps (19/21 unaided against 21/21 with landmine). The gap shows up when the request reads like a real one.
  • The hook alone didn’t measurably help. Telling the agent up front did, which is why the command above writes the rules section.
